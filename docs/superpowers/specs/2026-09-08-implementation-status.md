# 全站可靠性升级实施记录

本记录对应已批准的 `2026-09-08-full-site-reliability-design.md`。分批发布不代表全项完成。

## 第一批：前端与计算回归

已实现（自动化覆盖计算、分页、关联数据及同步响应；界面另外进行浏览器检查）：

- 姓名独填不达到首次上传门槛；有效完成度与模块导航状态分开。
- 已上传会话允许同步后续清空的字段；云端列表不再过滤低完成度的历史档案。
- 流动资金排除长期锁定资产；补充档案数据保留手填的零起始资金。
- 月供按剩余月数折算，到期停止；未知期限显示持续月供假设。
- 删除成员前确认关联数量，关联金额保留为家庭归属。
- 无负债需要显式确认；保险 10%–20% 的结论与状态颜色一致。
- 教育分项保留已知培训、食宿与学费，没有依据的不再虚构比例拆分。
- 顾问搜索结果同样每页五条。
- 未配置云端时写入/删除明确失败；旧同步响应不能确认较新的本地编辑，也不能改变另一客户状态。
- 客户网络重新连通时重新尝试自动同步；这尚不等于已完成持久队列和冲突处理。
- 储蓄险未启用提款时不校验默认提款年龄；批量撤销只影响相应格子，保留之后的独立修改。
- 放大窗口就地显示计算错误并可恢复；非法数字有文字反馈。
- 现金流放大窗口使用原生模态框；默认隐藏空白列，批量覆盖明确显示范围并确认。
- 储蓄险场景展示可动用现金及首次不足年份，不把保单余额当现金。
- 报告资产负债默认展开；隐私输入补充编辑提示；移除过期邀请码措辞与密码数字键盘限制。

浏览器检查：390、834、1440 CSS 像素关键路径；手机现金流模态窗口页面宽度 390/390，iPad 834/834，桌面储蓄险 1440/1440。桌面放大表格输入负数后显示错误，点击恢复重新呈现 11 行。尚未验证真实设备软键盘。

发布：第一批前端提交 `5e24ca7`，Actions `34198708624` 成功；线上入口引用 `index-B8YOOR2x.js`，与本地构建一致。102 项测试通过。

## 第二批：邀请码访问保护

增量文件：`supabase/migrations/202609080001_intake_access_guards.sql`。

- 新档案必须由已兑换的有效邀请码签发令牌；已有旧档案只允许匹配旧令牌访问。
- 撤销后拒绝旧令牌的下一次云端读写；第三次有效登录不会因兑换次数达到上限而立即失效。
- 顾问按邀请码创建者查看与修改自填记录；无邀请码历史档案仅兼容原 jojo 工作区。
- 原实现改为私有函数，取消匿名和 authenticated 执行权限，防止绕过保护层。
- 访问与撤销采用一致的行锁顺序；兼容原有 RPC 名称，不要求立即清除旧会话。

验证：在独立 `audit_intake_20260908` schema 内复制表结构和函数，不复制客户数据；使用临时数据验证邀请码绕过、第三次登录、撤销读写、顾问隔离、历史访问、私有函数授权、未提交撤销和重复迁移，全部通过后回滚。只读确认测试 schema 不存在。

已应用到用户确认的生产项目。迁移事务内比较客户文档与完整邀请码记录的摘要，确认没有改变业务内容、令牌或次数。Supabase 返回 `Applied: access guards; customer documents and invitation data unchanged`。
