# 医疗保障计算设计

## 目标与已确认口径

顾问模式新增独立入口“医疗保障计算”。同一被保险人可以添加多份保险，逐份计算并汇总年保费及缴费期总保费。客户自测模式不可进入。不改动客户档案、已有现金流或储蓄险功能，不新增方案库或云端数据表。

用户确认：所有折扣与优惠均不计入，包括推广、期满、EB 和保额档位折扣。保费采用原表基础费率；不能只隐藏优惠开关而仍在公式中扣除。

## 产品及原始依据

来源为用户提供的 e-1-toolbox-2026-08-03.xlsx，仅提取以下计算页及其必要费率依赖：

- CIM3：实际页名 CIM3 BCIM3；诚保一生危疾保。本次不另列 BCIM3 胎儿产品。
- CIE3：危疾加护保 III。
- CIP2：危疾首护保 II。
- 必要依赖：dataCIM、dataCIE、dataCIP 及 Notes 中产品名称和汇率常量。

这三个都是危疾产品。入口沿用用户指定的“医疗保障计算”，页面说明限定当前产品范围，不把它们描述为住院费用报销险。

已核对：三个主表 C3/C4/C5 分别为年龄、性别、吸烟，F3/F4/F5 为保额、供款期、币种。CIM3 和 CIP2 另使用 C6 地区。原表 999 为读取共享 Notes 的内部标记，不作为用户年龄选项。

## 页面结构

1. 顶部客户基础信息：投保翌年岁（明确 ANB 口径）、性别、是否吸烟、地区 A/B。无需客户姓名，避免另建档案关联。地区的业务解释必须沿原表核验，不擅自把 A/B 映射成国家或居住身份。
2. 初始一张保险卡：产品、保额、供款期、保单/显示币种。新增保险生成独立 ID，支持同产品不同保额组合，修改一张卡不能改变另一张。
3. 每卡显示年保费与该卡总保费。“展开明细”默认关闭；展开提供原表对应年度、年龄、每年供款、累计供款及保障/现金价值相关明细，保证与非保证项目分开，不能把现金价值当保费或保证赔付。取消无关优惠列。表格仅内部横向滚动。
4. 新增保险按钮在卡片列表下方。已填写卡片删除需确认；空白卡可直接移除。
5. 底部组合合计：首年保费合计、缴费期总保费。另提供默认收起的逐年组合保费，显示各产品缴费期结束后年支出下降，避免暗示首年合计永久不变。
6. 独立工具仅保存按顾问隔离的当前浏览器会话草稿，不添加命名方案、导入导出或应用客户入口。读取失败给出提示且不覆盖坏数据。

## 供款期、币种与计算

- CIM3 支持 5/10/15/20/25 年；CIE3 支持 10/15/20/25 年；CIP2 支持 10/15/20/25/30 年。按实际年龄/供款期费率可用性进一步约束；无费率或非法组合标记无法计算，不能用 0 元代替。
- 基础费率按照产品、年龄、性别、吸烟、适用地区及供款期查表。金额按原表每千元保额费率、保单与显示币种口径计算，保留原表取整方式。
- CIM3 C20、CIE3 C17、CIP2 C19 的保额折扣覆盖为 0；推广等输入关闭，并核对每年优惠扣减项确实为 0。原始源文件不修改。
- 按原表区分 USD、HKD、HKD-U、RMB-U。港币或人民币显示的美元保单仍应明确保额单位为美元，不把显示币种当成承保币种。
- 组合统一汇总为人民币，折算汇率可编辑、显示来源日期与“测算假设”，默认来自原表 Notes。单卡保留所选显示币种。不同币种不能直接相加。
- 首年合计为所有有效卡片第一缴费年度的保费之和；总保费为所有保险各缴费年度保费之和。无折扣时应与每卡年保费乘供款期一致，以年度明细之和作为实现口径。
- 各卡从同一投保年度起算。任何一张已添加保险缺少必要输入或计算失败，完整合计显示待完善，不以其余卡片部分金额冒充总额。

## 技术方案

采用独立产品适配器加现有受限公式解释器。较只移植保费公式，复用原公式更能保持展开明细与主表一致；不在网页嵌入 Excel，也不以缓存结果冒充输入变化后的重算。

- 新增限定提取脚本和独立数据包，不复制完整工作簿、作者信息、私人链接、宏或无关页卡。
- 医疗计算适配器独立管理覆盖值、无折扣策略、校验及汇总。只有需要且已有测试保护时才扩展共享公式解释器；不能使储蓄险结果漂移。
- UI 按需加载数据与计算器。App 中顾问导航、顶部标题及移动导航加入新视图；自测路由守卫同步排除。
- 输入更改后重新计算，各卡局部错误可修正；切换产品后无效供款期显式重置为该产品支持项，不能留下不可见旧值。
- 不通过网络上传工作簿或测算输入，不需要 Supabase migration。

## 验收门

1. 提取前后源文件不变；保留版本和数据来源说明。
2. 三个产品分别覆盖男女、吸烟/不吸烟、所有供款期、地区、币种、年龄边界、空白/零/负值及不存在费率组合。
3. 保额折扣阈值两侧验证不产生优惠；原表优惠开关改变不影响“无折扣”模式结果。
4. 以独立查表计算核对保费；在一次性临时副本中关闭优惠、折扣后用可用原生表格引擎验证代表场景及年度明细。缓存值只作为基线，不算重算证明；不可验证的明细必须明确标示，不编造。
5. 多卡独立编辑、同产品重复添加、删除确认、明细默认折叠、异币汇总、不同缴费期总额、无效卡阻断合计均有测试。
6. 现有全套测试与构建通过；390/834/1440 CSS 像素检查，页面不横向溢出，移动导航四入口可用，表格滚动不推宽页面。真实设备未测不宣称通过。
7. 发布前审查暂存区及敏感内容，仅提交范围内文件；发布后核对 Actions 和线上资源。
